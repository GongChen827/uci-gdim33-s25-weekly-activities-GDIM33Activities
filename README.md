### Activity 2
1. I think the Fraction node is used for making the shine movement loop, which the Time node just keeps increasing forever, but Fraction only keeps the decimal part of that value, so it will repeatedly go from 0 to almost 1 and then start over. And when the looping value is added to the UV coordinates of the Shine texture, the shader samples a moving part of the texture, which will make the shine look animated.
2. The reason why the Shine texture needs to be black by default is that the shader uses an Add node in order to combine the shine texture with the original sprite texture. And black is basically 0 in color math, so adding black does not change the original sprite, and if the default texture were white, every sprite using the shader will become brighter, even when I did not want a shine effect.
3. The building texture is only a default preview value in the Shader Graph, and for the actual SpriteRenderer objects, I think Unity will automatically fill the MainTex property with the sprite assigned to that SpriteRenderer. So even though the Shader Graph may use a building texture for preview, each sprite in the scene will still use its own SpriteRenderer sprite as the real MainTex.
4. We are multiplying Time by ShineSpeed before the Fraction node because that can change how quickly the looping 0 to 1 value cycles, which means that fraction(time * ShineSpeed) makes the animation loop faster or slower. But if we did fraction(time) * ShineSpeed instead, the loop value could go beyond the normal 0 to 1 UV offset range, which can make the movement look less clean. And by putting the speed inside Fraction, it will keep the motion looping smoothly while still controlling how fast it moves.
